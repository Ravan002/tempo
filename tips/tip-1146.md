# TIP-1146: T13 Hardfork Meta TIP

## Abstract

The proposed T13 hardfork activates multi-block Tempo imports for Zones and a
native Nitro-backed Zone verifier, including a temporary proofless settlement
fallback. It also makes Tempo's automatic block system calls explicit. This meta
TIP collects the implementation fixes and additional T13-gated proposals under
review, followed by the related TIPs.

## Motivation

This meta TIP collects the T13 upgrade scope and implementation links for review,
following the [T12 meta TIP](./tip-1116.md). PR status identifies implemented work
and proposals awaiting review; an open PR does not establish release inclusion.

## Assumptions

Tempo and Zone operators coordinate activation, compatible settlement ABIs, and
prover builds. Nitro settlement requires approved release PCR measurements. This
draft does not assign activation dates or replace the individual TIPs' review gates.

# Changes

The merged changes below are gated on T13. Their implementation does not imply
that T13 has activated on a public network.

## 1. Activate multi-block imports and the updated Zone runtimes

**PRs**: [#7521](https://github.com/tempoxyz/tempo/pull/7521) · **Author**: @shekhirin · **Status**: Merged

Activates [TIP-1096](./tip-1096.md) at T13, replacing the shared Zone portal,
verifier, and messenger runtimes and initializing the token-enablement cursor
for newly created portals. Zones can catch up through bounded header-only
imports before processing pending deposits and token enablements in a full block.
Existing portals follow TIP-1096's cursor-initialization and migration rules.

## 2. Activate the native Nitro-backed Zone verifier

**PRs**: [#7287](https://github.com/tempoxyz/tempo/pull/7287), [#7626](https://github.com/tempoxyz/tempo/pull/7626) · **Authors**: @rkrasiuk, @decofe · **Status**: Merged

Activates [TIP-1098](./tip-1098.md) at the shared verifier address. Native dispatch
validates AWS Nitro attestations, enclave measurements, and the signed batch
commitment. The activation fix aligns verifier registration and dispatch with
the T13 portal ABI; earlier forks retain the legacy verifier.

## 3. Bind Nitro proofs to the settled Zone height

**PRs**: [#7689](https://github.com/tempoxyz/tempo/pull/7689) · **Author**: @shekhirin · **Status**: Merged

Adds `nextZoneHeight` to the verifier ABI and signed Nitro commitment, preventing
reuse of a valid proof with a different settled height. Updates the T13 portal
and verifier runtimes; the matching prover and portal changes in
[Zones #1467](https://github.com/tempoxyz/zones/pull/1467) must ship together.

## 4. Allow the temporary NoProof rollout mode

**PRs**: [#7891](https://github.com/tempoxyz/tempo/pull/7891) · **Author**: @0xrusowsky · **Status**: Merged

Adds TIP-1098's temporary `NoProof` mode (`0x02`). It requires an empty proof and
retains portal continuity, settlement, and sequencer-quorum checks while skipping
Nitro validation. The quorum signs the mode and settlement inputs. During this
rollout exception, quorum-authorized settlement remains trusted; a later hardfork
must disable the fallback to require Nitro proofs for every batch.

## 5. Preserve Zone runtimes supplied at genesis

**PRs**: [#7813](https://github.com/tempoxyz/tempo/pull/7813) · **Author**: @decofe · **Status**: Merged

When T13 is already active at the genesis timestamp, preserves the Zone runtime
code supplied by genesis instead of replacing it. Chains activating T13 after
genesis retain the pinned-runtime upgrade path.

## 6. Select Tempo's block system calls explicitly

**PRs**: [#7710](https://github.com/tempoxyz/tempo/pull/7710) · **Author**: @DaniPopes · **Status**: Merged

Implements [TIP-1119](./tip-1119.md), retaining parent-block-hash storage and
committee updates while disabling Ethereum beacon-root and execution-request
processing. This prevents Ethereum builder-contract requirements from blocking
Tempo execution.

## Additional T13-gated proposals under review

These open PRs propose T13 activation but are not merged. Inclusion remains
subject to review and an explicit upgrade-scope decision.

### 7. Keep explicitly zeroed spending limits at zero on refund

**PRs**: [#7800](https://github.com/tempoxyz/tempo/pull/7800) · **Author**: @0xShadowX · **Status**: Open

Prevents a same-transaction refund from restoring an access key's spending limit
after an administrator explicitly sets it to zero. Preserves the legacy behavior
for migrated pre-T3 rows and the periodic-limit zero encoding.

### 8. Reject unclaimable guarded precompile payouts

**PRs**: [#7618](https://github.com/tempoxyz/tempo/pull/7618) · **Author**: @kriss39 · **Status**: Open

Reverts with `PolicyForbids` when a blocked precompile payout would create a
receipt recoverable only by the originating precompile. This preserves the
calling precompile's accounting instead of stranding funds in ReceivePolicyGuard;
claimable recovery paths keep their existing behavior.

### 9. Try an ordered fallback list of fee tokens

**PRs**: [#8154](https://github.com/tempoxyz/tempo/pull/8154) · **Author**: @klkvr · **Status**: Open

Implements the proposed [TIP-1115](https://github.com/tempoxyz/tempo/pull/7597)
with ordered `[pathUSD, OUSD]` fallback from T13, shared execution and estimation
resolution, and pool revalidation. The specification's protocol version remains
`TBD`; T13 is the implementation proposal's gate.

### 10. Add separate policy membership selectors

**PRs**: [#8220](https://github.com/tempoxyz/tempo/pull/8220) · **Author**: @decofe · **Status**: Open

Implements the proposed [TIP-1141](https://github.com/tempoxyz/tempo/pull/8221)
with separate whitelist and blacklist add/remove selectors from T13. Access keys
can be scoped to one operation while existing policy authorization, errors, and
events remain in use. The specification's protocol version remains `TBD`.

### 11. Meter access-key spending on Zone withdrawals

**PRs**: [#8238](https://github.com/tempoxyz/tempo/pull/8238) · **Author**: @legion2002 · **Status**: Open

Proposes [TIP-1144](https://github.com/tempoxyz/tempo/pull/8238), adding ZoneOutbox
to the TIP-1035 Implicit Approval List from T13. The coordinated outbox change uses
`system_transfer_from` for the caller's withdrawal funds so AccountKeychain
spending limits apply, without requiring an allowance to the outbox.

# Tooling

Operators must deploy compatible Tempo, Zone, and prover revisions and finalize
release measurements before Nitro settlement. Merged
[#8046](https://github.com/tempoxyz/tempo/pull/8046) stores hardfork-specific PCRs,
the source commit, and the digest-pinned prover image in `pcrs.json` and checks
them against the shipped enclave image in CI. The manifest is currently empty,
so production Nitro verification has no approved measurements.

# Observability

Existing settlement events, traces, and operator alerts cover the merged scope;
operators should alert on `NoProof` fallback as specified in TIP-1098. Open
[#8047](https://github.com/tempoxyz/tempo/pull/8047) proposes a `ProofVerified` event
with the accepted PCRs and a corresponding T13 portal runtime update. Open
[#8095](https://github.com/tempoxyz/tempo/pull/8095) proposes the
`tempo zone-pcr-history` inspection command. Neither is part of the merged scope.

# Threat Model

Nitro mode relies on AWS attestation and approved enclave measurements; settlement
inputs and the settled Zone height must match the attested commitment. Temporary
`NoProof` mode retains the sequencer-quorum trust assumption. The individual TIPs
define their full trust boundaries and adversarial cases.

# Invariants

- Fork-gated changes preserve the historical behavior before T13.
- Tempo and Zone settlement ABIs, commitments, and prover builds agree at activation.
- Accepted Nitro proofs bind every public settlement input, including Zone height.
- `NoProof` accepts only an empty proof and retains quorum and settlement checks.
- T13-at-genesis chains preserve their supplied runtime state.
- Automatic block system calls follow TIP-1119's history and committee rules.
- Open proposals remain subject to their own review and activation decisions.
