# TIP-1146: T13 Meta TIP

## Abstract

T13 activates multi-block Tempo imports for Zones, native Nitro-backed batch
verification with a temporary proofless fallback, and explicit block system
calls. It also adds ordered fee-token fallback. This meta TIP links the
individual T13 TIPs and collects additional protocol changes.

## Motivation

This meta TIP collects the T13 upgrade scope and implementation links for review,
following the [T12 meta TIP](./tip-1116.md).

## Assumptions

Tempo and Zone operators coordinate activation, compatible settlement ABIs, and
prover builds. Nitro settlement requires approved release PCR measurements.
Implementation PRs marked open below still require completion and review.

# Additional protocol changes

These changes are not covered by an individual T13 TIP. They activate at T13;
pre-T13 behavior is unchanged. PR status records whether the implementation has
merged.

## 1. Preserve Zone runtimes supplied at genesis

**PRs**: [#7813](https://github.com/tempoxyz/tempo/pull/7813) · **Author**: @decofe · **Status**: Merged

When T13 is already active at the genesis timestamp, preserves the Zone runtime
code supplied by genesis instead of replacing it. Chains activating T13 after
genesis retain the pinned-runtime upgrade path.

## 2. Use recipient policy for bridged TIP-20 credits

**PRs**: [#8286](https://github.com/tempoxyz/tempo/pull/8286) · **Author**: @decofe · **Status**: Merged

Zone deposits, withdrawal bounce-backs, and refund claims credit escrowed assets
using TIP-403 `Recipient` authorization instead of `MintRecipient`. Receive-policy
checks and refund behavior remain unchanged.

# Tooling

Operators must deploy compatible Tempo, Zone, and prover revisions. The Zone
height commitment update requires the matching portal and prover changes in
[Zones #1467](https://github.com/tempoxyz/zones/pull/1467).

Merged [#8046](https://github.com/tempoxyz/tempo/pull/8046) records hardfork-specific
PCRs, the source commit, and the digest-pinned prover image in `pcrs.json` and
checks the measurements against the shipped enclave image in CI. The approved
release measurements must be added before production Nitro settlement; the
manifest is currently empty. Merged
[#8005](https://github.com/tempoxyz/tempo/pull/8005) permits custom PCRs only in
feature-enabled devnet builds, which refuse to start on mainnet or Moderato.
Merged [#7832](https://github.com/tempoxyz/tempo/pull/7832) exposes local proof
verification for shadow provers without changing on-chain dispatch.

Open [#8095](https://github.com/tempoxyz/tempo/pull/8095) adds
`tempo zone-pcr-history` to inspect PCRs observed in settled Nitro batches. This
inspection tool does not change T13 validity rules.

# Observability

The individual TIPs define their events and monitoring requirements. Operators
should alert on `NoProof` fallback as specified in TIP-1098. Open
[#8047](https://github.com/tempoxyz/tempo/pull/8047) adds `ProofVerified` with the
accepted PCRs and changes the T13 portal's verifier call from `STATICCALL` to
`CALL`.

# Threat Model

Nitro mode relies on AWS attestation and approved enclave measurements; every
public settlement input must match the attested commitment. Temporary
`NoProof` mode retains the sequencer-quorum trust assumption until a later
hardfork disables it. The individual TIPs define their full trust boundaries.

# Invariants

- Fork-gated changes preserve historical behavior before T13.
- Tempo and Zone settlement ABIs, commitments, and prover builds agree at activation.
- Accepted Nitro proofs bind every public settlement input, including Zone height.
- `NoProof` accepts only an empty proof and retains quorum and settlement checks.
- T13-at-genesis chains preserve their supplied Zone runtime code.
- Automatic block system calls follow TIP-1119's history and committee rules.
