# TIP-1146: T13 Meta TIP

## Abstract

T13 activates multi-block Tempo imports for Zones, native Nitro-backed batch
verification with a temporary proofless fallback, and explicit block system
calls. It also adds ordered fee-token fallback. This meta TIP links the
individual T13 TIPs and collects additional protocol changes.

## Motivation

This meta TIP collects the T13 upgrade scope and implementation links for review,
following the [T12 meta TIP](./tip-1116.md).

## Assumptions

Tempo and Zone operators coordinate activation, compatible settlement ABIs, and
prover builds. Nitro settlement requires approved release PCR measurements.

# Additional protocol changes

These changes are not covered by an individual T13 TIP. They activate at T13;
pre-T13 behavior is unchanged. PR status records whether the implementation has
merged.

## 1. Preserve Zone runtimes supplied at genesis

**PRs**: [#7813](https://github.com/tempoxyz/tempo/pull/7813) · **Author**: @decofe · **Status**: Merged

When T13 is already active at the genesis timestamp, preserves the Zone runtime
code supplied by genesis instead of replacing it. Chains activating T13 after
genesis retain the pinned-runtime upgrade path.

## 2. Use recipient policy for bridged TIP-20 credits

**PRs**: [#8286](https://github.com/tempoxyz/tempo/pull/8286) · **Author**: @decofe · **Status**: Merged

Zone deposits, withdrawal bounce-backs, and refund claims credit escrowed assets
using TIP-403 `Recipient` authorization instead of `MintRecipient`. Receive-policy
checks and refund behavior remain unchanged.

# Tooling

- Update Zone payload builders, block decoders, RPC encoders, sequencers, provers,
  and runtimes for the T13 settlement ABI and explicit header-only/full imports.
- Drain deposit and token-enablement backlogs to TIP-1096's migration bounds
  before activation.
- Finalise the approved Nitro PCR measurements in `pcrs.json` and the matching
  digest-pinned prover image before Nitro settlement.
- Update fee-token tooling for the ordered `[pathUSD, OUSD]` fallback while
  preserving existing explicit choices, preferences, and inference rules.
- Supply the intended Zone runtime code in genesis for chains starting with
  T13 active.
- Use TIP-403 `Recipient` authorization when prechecking bridged deposits,
  withdrawal bounce-backs, and refund claims from T13.

# Observability

- Decode both legacy and T13 `TempoAdvanced` and `BatchSubmitted` signatures by
  topic, including the new token-enablement cursor.
- Track header-only recovery through `TempoBlockFinalized`; header-only blocks
  do not close a settlement batch. A `NO_QUEUE_INDEX` settlement must not create
  or overwrite a withdrawal queue record.
- Alert on settlement using `NoProof`; use verifier traces to inspect proof
  rejection and gas failures.
- Read receipt `feeToken` and `feePayer` fields for fallback payments; no new
  fee events are required.
- Use existing TIP-20 credit logs, refund state, and transaction traces for
  recipient-policy outcomes. Compare shared Zone runtime code with genesis
  allocations on T13-at-genesis chains.
